# 구현·검증 결과 — 0.1 핵심 버전

이 문서는 현재 제공한 소스와 실제 테스트 결과를 설명합니다. 정식 상용 수준 완성 선언이 아닙니다.

## 실제 실행 환경

- Linux x86_64, Python 3.12.14, PySide6/Qt 6.8.3
- 시스템 FFmpeg 6.1.1 (libx264 / libass 사용)
- Qt Multimedia 내부 FFmpeg 7.1, offscreen 플랫폼
- 한글 Noto Sans KR 글리프를 렌더한 영상 프레임을 육안 확인
- 최종 실행: `PYTHONPATH=. python3 -m pytest -q`
- **24 passed** — 이번 Portable 수정 후 Linux 실행. 정확한 시간은 test-output.txt 참고.
- 테스트 원문 로그: `test-output.txt`

## 기능 및 검증

| 항목 | 구현 및 실제 확인 |
|---|---|
| 실제 영상 분석 | FFprobe로 길이/영상/오디오 확인, GUI worker에서 불러오기 |
| 긴 원본 탐색 구조 | 36,005초 MKV를 생성, 35,999~36,001초만 seek 후 2초 MP4 출력 |
| IN/OUT | GUI 입력 0.25~1.25초를 클립으로 가져오는 통합 테스트 |
| 컷 편집 | 분할/삭제/순서 변경/복제/OUT 조절, JSON 및 엔진에 반영 |
| undo/redo | Qt UI 테스트에서 분할·취소·복원·삭제·재정렬 확인 |
| 세로 배치 | crop, fit, blur, split 각각 렌더 성공 |
| 상·하단 split | 같은 원본 크롭 두 영역 합성. 픽셀 검사로 두 번째 클립 순서 확인 |
| 수동 자막 | 한글 burn-in 전후 픽셀 차이 검증, ASS 생성 |
| 자막 애니메이션 | fade, pop, slide, scale 실제 렌더 성공. pop/scale은 동일 구현 |
| 자막 시간 | 0.3초 없음 / 0.7초 표시 / 1.2초 없음 픽셀 검사 |
| BGM/원음 | 별도 파일 믹싱, 음량, 페이드, 리미터. 출력 PCM 신호 확인 |
| 컷 오디오 싱크 | 원본 1.5초 톤 시작을 1초부터 자른 후 0.5초 ±60ms에서 검출 |
| 저장/복원 | 프로젝트 round-trip 비교, GUI 저장, UTF-8 원자 저장 |
| 720p 출력 | 720×1280 H.264/AAC 실제 출력/전 구간 디코드 확인 |
| 1080p / 60fps | 1080×1920, 60/1 FPS 단기 샘플 출력 확인 |
| 미리보기 | 실제 렌더 결과를 Qt QMediaPlayer로 재생, 유효 QVideoSink 프레임 확인 |
| 취소 | 실행 중 cancel, 프로세스 종료, 임시 폴더 제거, 기존 출력 보호 |
| 비파괴 보호 | 원본 SHA-256 변경 없음, 원본과 같은 출력 경로 거부 |
| 캐시 | 한 프레임 JPEG, 최대 60초/8kHz mono 파형 생성 |
| UI | 실제 네이티브 위젯, 다크 스타일. 1280×840 오프스크린 렌더 육안 확인 |

10시간 테스트 파일은 **16×16, 1fps 무음 합성 영상**입니다. 장시간 timestamp 탐색 구조를 검증한 것으로, 실제 고해상도 10시간 방송에서의 성능 테스트를 대신하지 않습니다.
샘플 MP4는 `demo/StreamShort-Demo.mp4`, 실제 한글 자막과 BGM을 포함하는 720×1280 영상입니다.
컷의 오디오 시작 시간 검증은 특정 합성 입력에 한정됩니다. 모든 VFR/다중 스트림/손상 방송의 싱크를 보장하지 않습니다.

## 구현했지만 해당 환경에서 검증하지 않은 항목

- Windows 10/11 네이티브 앱 실행, EXE 패키징, 드라이버/오디오 장치 호환성
- NVENC/QSV/AMF 하드웨어 인코딩과 CPU 대체 경로의 실제 GPU 실행
- 실제 8GB 또는 16GB RAM 노트북 성능 및 배터리/메모리 사용량
- macOS 실행/서명/배포
- 실사용자가 폰트 목록에서 선택한 모든 폰트의 Qt/libass 일치성
- 장시간 실제 방송의 VFR, HDR, 다중 영상/오디오, 손상 입력, 회전 메타데이터
- Windows 한글/특수문자 경로 전체 조합
- 자동 저장 복구/최근 목록/재연결/프리셋/가이드 설정을 Windows에서 사람이 수행하는 사용성 검증

## 전체 요구에서 아직 미구현 또는 제한된 부분

- 실시간 합성 미리보기: 변경 후 선택 쇼츠를 렌더해 갱신해야 함
- 캔버스에서 직접 크롭 사각형 핸들 조절: 현재 숫자 영역 입력과 crop 위치 드래그
- 다중 선택, 리플 편집, 정교한 클립 경계 스냅, 트랙 잠금/뮤트/솔로
- 원본 오디오의 영상 트랙에서 독립 추출/분리
- 영상/오디오 트랙 내부 전체 썸네일/파형: 현재 좌측 선택 항목 분석창만 제공
- 게임 화면/캠 영역 자동 탐지: 수동 크롭만 제공, AI 없음
- GPU 디코딩 자동 선택 및 모든 단계 GPU 합성
- 출력 단계 중간 정규화는 CPU 사용. 최종 단계만 선택한 하드웨어 인코더 사용 가능
- 자막 크기 기반 팝업/확대 효과는 현재 같은 애니메이션
- 자주 사용하는 효과음 즐겨찾기
- 다중 파일 드롭: 첫 번째 파일만 가져옴
- IN/OUT 지점을 드래그하는 전용 핸들: 시간 입력/현재 위치 지정 사용
- 프로그램 이름 변경 UI, 상세 출력 비트레이트/색공간/HDR 설정
- 자동 캐시 용량 상한/LRU, 충분한 디스크 공간의 사전 보장
- 설치 마법사, 코드 서명, 자동 업데이트, Windows EXE 완성 파일

## 배포 상태

실행 가능한 **소스 프로젝트**, Windows 빌드 spec/PowerShell, 사용 설명서와 테스트를 제공합니다.
현재 소스에는 Windows FFmpeg/FFprobe EXE를 포함하지 않았습니다. Windows에서 의존성 준비 후 빌드해야 합니다.
프로그램 배포 시 Qt/FFmpeg 대응 소스 및 고지 제공은 선택한 바이너리에 맞춰 수행해야 합니다.
이 ZIP이 라이선스 준비를 마친 Windows 설치파일이라는 주장은 하지 않습니다.


## Portable 배포 구성 변경 후 검증

- 기존 19개 영상/Qt 테스트와 배포 관련 5개 검사, 총 **24개 통과**.
- EXE 안에 넣을 동일 self-test를 Linux 소스로 실행: **18개 검사 통과**.
  근거: `validation/linux-source-self-test.json` (`frozen: false`, `platform: linux`).
- 검사에는 영상 불러오기, IN/OUT, 분할/삭제/순서 변경, 프로젝트 복원, 원음 음소거 + BGM 신호, 한글 자막 실제 픽셀 차이, 1080×1920 H.264/AAC 출력, 전체 디코드, Qt 미리보기 프레임이 포함됩니다.
- frozen 상태에서 PATH의 시스템 FFmpeg로 대체하지 않음, 쓰기 가능한 Portable Data 및 AppData 대체, ZIP 경로 탈출 거부, DLL 누락 거부, 실패한 self-test의 배포 ZIP 생성 차단을 확인했습니다.
- GitHub Actions YAML 파싱과 기대하는 jobs/runner 구조를 검사했습니다.
- PowerShell 스크립트는 코드 검토했지만 현재 환경에 PowerShell/Windows가 없어 실제 실행하지 않았습니다.
- **Windows EXE 빌드, GitHub Actions 실제 실행, 동봉 DLL 검증의 Windows 실행, PATH 격리된 Windows EXE self-test 및 클린 Windows Sandbox 테스트는 모두 미실행**입니다.
- `Validate-Clean-Windows.cmd/ps1`은 생성된 Portable 폴더에서 네트워크 없는 Windows Sandbox 검증을 실행하도록 준비한 스크립트이며 이번에 실행하지 않았습니다.
- 최종 제공한 수정 ZIP은 자동 Windows 빌드 프로젝트입니다. 실행용 Portable ZIP이 아니고 EXE를 포함하지 않습니다.
- 워크플로를 실제 실행하여 빌드/검사가 통과한 경우에만 `StreamShortStudio-Windows-x64-Portable.zip`을 생성합니다.
